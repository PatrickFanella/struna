# Hosted ownership gate — #94

November 15, 2026. Scratch-only qualification for roadmap #77. Production still refuses `STRUNA_HOSTED_PRACTICE=1`; this change does not enable it.

The [route inventory](hosted-route-inventory.json) records each literal route registration, its source and its effective hosted boundary. `server/auth/isolation.test.ts` compares that inventory with every registration in server source, so additions require classification. The gate also compares the unique account routes with the actual in-memory hosted routers registered for a verified account, independently of the source scan. Duplicate owner registrations such as Today are marked account-scoped because hosted mode registers its own replacement; owner handlers are never registered there.

The direct identity dispatcher in `server/auth/hosted.ts` additionally handles GET/HEAD `/api/account`, `/api/app` and `/api/health`, POST `/auth/login`, GET `/auth/callback` and POST `/auth/logout`. Account status and health are public/redacted; app-info resolves only the verified session. Login/callback enforce browser flow, nonce/PKCE and allowlisted return destinations; logout requires origin, app header and session CSRF. Existing `hosted.test.ts` tests those branches. Only GET/HEAD `/`, build-owned `/assets`, `/brand`, `/starter` and the manifest pass through to static serving. Production `/try` gets an explicit guest bootstrap. Unknown and unported routes are consumed by the hosted dispatcher and denied, including library, tabs, media, vault reads, CLI provider/device-login, guide/review process, image cache and plan-candidate Apply routes. Static paths never resolve against workspace/cache roots.

The combined HTTP gate uses A, B and anonymous requests, distinct private canaries, raw/range file and take routes, no-store metadata, redacted provider status, spoofed session headers, concurrent writes, account switching, sign-out and idle expiry during a delayed stream. Late output is discarded; no global owner database appears. Existing focused account suites additionally cover traversal, symlinks, delayed uploads, foreign conversation IDs, authenticated encryption/substitution, key replacement and revocation. Stand-ins have no provider credentials or outbound model access.

`node scripts/verify-hosted-isolation.ts` runs the built app through the scratch identity dispatcher, with an anonymous browser and sequential A/B sessions in one context. It checks anonymous denial, distinct profile form values, stale cookie/header rejection, focus-triggered account invalidation and sign-out redaction. It enumerates built text assets, starter/brand files and the manifest and scans their HTTP responses for account/owner canaries and account IDs. Cache and account filesystem paths are separately denied by HTTP tests. The scratch asset proxy uses the same build and bootstrap shape; it is not a production edge/OIDC test. CI runs this gate alongside the existing two-account and guest browser suites. `server/app.test.ts`, `socket.test.ts` and the Studio smoke retain separate owner-mode regression coverage.

Commands: `pnpm typecheck`, `pnpm test`, `pnpm build`, `node scripts/verify-hosted-isolation.ts`, `node scripts/verify-hosted-practice.ts`, and `node scripts/smoke-wave-one.ts`.

Independent review of the complete ownership boundary and an exact deployment candidate remains required before public multi-user exposure. Real identity registration, provider charges, Safari/device/audio and assistive speech remain outside this scratch gate.

Local results: all 359 tests pass, typecheck and production build pass, the built-browser isolation gate passes, and the owner Studio smoke passes its compact header/timer matrix. Independent code review identified inventory/runtime and static/cache coverage gaps; both were corrected before delivery.
